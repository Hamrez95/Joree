# ساختار فرانت

به‌روزرسانی ۸ نوامبر: میزبان `windows/Joree.Desktop` با .NET / WebView2 اضافه شد. `nativeHost.ts` فرمان‌های محدود پنجره و ذخیرهٔ snapshot را به آن می‌فرستد. SQLite ویندوز مسئول ذخیرهٔ نسخهٔ نصب‌شده است و localStorage فقط کش رابط است؛ نسخهٔ مرورگر همچنان localStorage دارد. میزبان فقط محتوای محلی با origin ثابت را به فرمان‌ها راه می‌دهد. SQL یا فایل‌سیستم عمومی به صفحه ارائه نمی‌شود. نصاب فقط در پوشه‌های کاربر و HKCU می‌نویسد. شرح زیر سابقهٔ ساخت اولیهٔ فرانت است.

`App.svelte` هماهنگ‌کنندهٔ صفحه‌ها و تغییرات داده است. `screens` صفحه‌های محصول، `lib/ConsoleShell.svelte` بدنهٔ مشترک و `lib` شامل آیکن، تزئینات، کارتریج، مدل درس، زمان‌بندی مرور و موتور بازی است. بازی‌ها فقط هنگام اولین مراجعه بارگیری می‌شوند و با خروج از صفحه حلقهٔ اجرا آزاد می‌شود.

ورودی Markdown در `lessons.ts` به مدل کارت تبدیل می‌شود. دادهٔ بازیابی‌شده پیش از جایگزینی اعتبارسنجی می‌شود. تغییرات داده در فرانت در `localStorage` ذخیره می‌شوند. رابط سیستم عامل در `desktop.ts` محدود به عملیات پنجره است؛ در مرورگر فراخوانی API دسکتاپ انجام نمی‌شود.

`src-tauri` فقط پوستهٔ اولیهٔ میزبان دسکتاپ است و در این محیط ساخته نشده است. لایهٔ Rust/SQLite محصول کامل هنوز وجود ندارد. مهاجرت از ذخیره‌سازی فرانت به فرمان‌های محدود Rust باید جداگانه انجام شود.
